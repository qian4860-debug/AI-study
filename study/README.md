## 怎么解释这个核心

以 A=[[1,−2,3],[−128,127,−1]]、B=[−1,2,−3] 为例，结果为 [−14,385]。每一项分别经过同步读取和乘加，第一行累加轨迹为 −1、−5、−14，第二行为 128、382、385。两个输出分别写入 C[0]、C[1] 的低 32 位。共执行 6 MAC、15 周期，从两个输入端口读取 48 字节、写出 32 字节。一次 MAC 按两次 operation 计数；这里没有真实工作频率，周期不能直接换算为实测时间。

修改入口明确：数据生成与实验形状在 verify.py，数学与布局在 reference.py，调度在 TPU.v，算术在 mac_pe.v。修改后重跑同一验证入口。接口合同改变时应先修改文档和独立黄金，再修改 RTL，不能仅让两个实现同时接受同一错误。

## 测量与下一阶段

results.json 的 cycles、reads、macs、writes 来自 RTL testbench 的边沿计数，并检查解析公式。M=2/K=3 案例额外把每个边沿的状态、行号、项号、部分和与 Python 周期模型精确比较。尾行不满四槽、K=1、K=254、正负极值、连续任务、启动后维度无效以及任务中途复位均进入回归。

单 MAC 是解释和定位错误的基线，资源与时序尚未综合实测。下一步依次进行：

1. 保留本版，设计预取使 MAC 连续工作，比较相同向量的周期与端口流量，验证最后一项排空。
2. 扩为四路输出驻留 PE，广播 B，消费 A 的四个槽；为尾行增加 mask。比较 MAC 利用率、读次数、周期，再用同一器件/约束综合检查 LUT/FF/DSP/WNS。
3. 加入小 MLP 的偏置、ReLU、逐层量化和重定标，对齐每层中间整数结果；训练数据与测试数据分开。此时才能讨论真实网络精度。
4. 选择一个成熟陀螺模块（如多项式校准），先定义单位、采样率、位宽、误差与闭环延迟预算，再映射到共享乘加核心。真实数据到位后按设备、温度和时间段划分测试集，对比传统方法。
