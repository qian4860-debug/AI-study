# 第002步 可配置长度整数点积

日期：2026年10月15日  
方向：为AI算法设计数字电路  
状态：本步骤 RTL、MATLAB 数值参考与仿真已通过；详细验收及综合状态见 REPORT.md。

## 1 本步骤目标与前置条件

将第001步固定4项点积扩展为可配置长度点积：

$$
y=\sum_{j=0}^{K-1}x_jw_j,\qquad 1\le K\le256.
$$

仍使用一个有符号8乘8乘法器复用和一个累加器。增加任务启动、长度快照、接收计数和非法配置处理。本步骤不增加偏置、激活、重量化和存储接口，便于分别定位问题。

进入条件：第001步的正常、极值、停顿、复位和连续任务测试通过，能够解释最后一个乘积怎样进入输出。现有 NYCU 单 MAC 基线已通过 66,045 项检查，但未取得原第001步固定4项模块及其原始向量。该前置项按未完整确认记录；本步骤额外覆盖固定 K=4、极值、停顿、复位和连续任务，详见 REPORT.md。

## 2 为什么先增加可配置长度

神经网络不同层的点积长度不同。可配置K把固定算术模块变成可服务多种形状的计算单元，同时引入位宽、边界、配置稳定性和任务控制问题。

本步骤完成后应能回答：为什么K不能直接用普通8位无符号数表示256？为什么计数按接受事件推进？为什么busy期间修改外部K不应改变当前任务？为什么最后一次输出仍需包含当前乘积？

## 3 数值与计数位宽

| 信号或状态 | 位宽 | 理由 |
|---|---:|---|
| x、w | 有符号8位 | 保持第001步输入范围 |
| product | 有符号16位 | 范围为[-16256,16384] |
| k_cfg、k_latched | 无符号9位 | 直接表示1至256；0和257至511非法 |
| accepted_count | 无符号9位 | 表示已接受数量，允许表示256 |
| acc、out_data | 有符号24位 | 覆盖256项完整精度累加 |

对所有合法K，和的范围为[-16256K,16384K]。K=256时为[-4161536,4194304]。23位有符号最大值4194303不足；24位有符号范围[-8388608,8388607]足够。因此本步骤无需截位、舍入和饱和。

product在加到acc之前显式符号扩展至24位。对全部16位乘积，高8位复制product[15]。如果使用拼接，应注意拼接表达式本身通常不带有符号属性，必须让扩展值、累加器及结果保持明确一致的有符号类型。

“256用8位0表示”也可以作为另一种编码设计，但它会改变非法值和软件接口语义。本步骤采用直接9位表示，不混用两种编码。

## 4 模块接口合同

| 信号 | 方向 | 定义 |
|---|---|---|
| clk | 输入 | 主时钟 |
| reset | 输入 | 同步高有效复位，优先级最高 |
| start | 输入 | 任务启动请求 |
| start_ready | 输出 | 空闲时为1，表示可接受启动 |
| k_cfg[8:0] | 输入 | 与启动请求一起采样的长度 |
| in_valid | 输入 | 当前操作数有效 |
| in_ready | 输出 | 正在运行且可接收数据时为1 |
| x、w | 输入 | 有符号8位操作数 |
| busy | 输出 | 正在执行合法任务 |
| out_data | 输出 | 有符号24位完整点积结果 |
| out_valid | 输出 | 合法任务完成后有效一拍，无输出背压 |
| cfg_error | 输出 | 接受非法长度启动后有效一拍 |

定义两个接受事件：start_fire=start AND start_ready，data_fire=in_valid AND in_ready。只有data_fire导致接收计数和部分和更新。

本教学核心每个运行周期均可接受一对操作数，因此非复位状态下in_ready=busy，start_ready=NOT busy。接收端没有额外内部停顿。未来增加存储或流水后，应重新定义可接受条件。

复位边沿不接受任何事务，无论边沿前ready为何值。复位清除busy、计数、配置快照、累加器、out_valid、cfg_error和out_data；环境也必须按复位语义取消该边沿的事务记录。

start与ready构成请求握手；发送端每次握手后必须撤销start或切换到下一个请求。busy期间start_ready为0，不接受启动；若请求一直保持到重新空闲，会在下一个可接受边沿启动，这是握手协议的预期行为。

## 5 任务启动与配置快照

空闲时接受start：若K合法，将k_cfg保存为k_latched，清零acc和accepted_count，置busy。若K非法，保持空闲并置cfg_error一拍，不产生out_valid，也不开始接收数据。

启动被接受的同一个边沿不接收操作数，因为该边沿前in_ready为0。合法启动后的下一边沿最早可接受第一对数据。此约定故意使启动和数据接受分开，减少边界歧义。

运行期间，外部k_cfg的变化不影响k_latched。所有结束判断只依赖k_latched，不再读取实时k_cfg。发送端无需保持k_cfg整个任务不变，但必须满足启动边沿的建立保持要求。

out_valid和cfg_error默认每拍清零，再由相应事件置位。out_data在非复位且未完成任务时保持上次结果。合法启动后的错误标记不会自动成为持续状态；本步骤使用一拍错误脉冲，后续CSR版本可改成粘滞状态并重新定义清除规则。

## 6 累加与结束判断

accepted_count表示当前任务在本边沿之前已经接收的操作数数量，启动后为0。data_fire时计算：

$$
sum\_next=acc+\operatorname{signextend}_{24}(product).
$$

使用至少9位的比较判断accepted_count+1是否等于k_latched。若不是最后一项，则保存sum_next并增加计数；若是最后一项，将sum_next写到out_data、置out_valid、清busy，并将acc和计数清零。

这里的“下一部分和”是组合计算值，不是已完成更新的寄存器值。非阻塞赋值在边沿后统一生效，不能依赖语句书写顺序让out_data读到acc的新值。

data_fire为0时，acc、计数和k_latched保持不变，任务继续等待。没有输入时允许无限等待；本步骤不包含超时机制。测试平台可设置仿真看门狗以结束错误测试，但不能把它描述成硬件超时功能。

## 7 时序示例

K=3，x=[2,-3,4]，w=[1,2,-1]，期望输出-8。以下表格按每个边沿处理后的状态记录；合法启动发生于C0。

| 边沿 | 事件 | busy | 已接受数 | 部分和 | 输出 |
|---|---|---:|---:|---:|---|
| C0 | 接受start，K=3 | 1 | 0 | 0 | out_valid=0 |
| C1 | 接受第1对 | 1 | 1 | 2 | 无新结果 |
| C2 | in_valid=0 | 1 | 1 | 2 | 无新结果 |
| C3 | 接受第2对 | 1 | 2 | -4 | 无新结果 |
| C4 | 接受第3对，任务完成 | 0 | 0 | 0 | out_valid=1，out_data=-8 |
| C5 | 可接受下一次start | 取决于新请求 | 0 | 0 | out_valid清零 |

K=1时，启动后的第一个data_fire即完成任务。C4边沿前仍为busy，因此C4不能同时接受下一任务启动；C5是最早的下一启动边沿。若源希望同边沿切换任务，需要另一套协议，不属于本步骤。

无输入停顿且无乘法流水时，从启动接受边沿到输出更新边沿经过K个时钟周期。启动前等待、输入停顿和任务间启动开销须分别计量。增加乘法流水后此公式不再直接适用。

## 8 先完成独立MATLAB参考

```matlab
function y = dot_int8_reference(x, w)
    assert(isa(x, 'int8') && isa(w, 'int8'));
    assert(isvector(x) && isvector(w));
    assert(numel(x) == numel(w));
    K = numel(x);
    assert(K >= 1 && K <= 256);
    products = int32(x(:)) .* int32(w(:));
    y = sum(double(products));
    assert(y >= -2^23 && y <= 2^23-1);
end
```

将函数保存为dot_int8_reference.m。当前点积范围内，double可以精确表示这些整数；此参考用于数值期望，不模拟硬件接受事件。

最先检查三个算例：K=1时x=-128、w=-128，输出16384；K=3时采用本章示例，输出-8；K=256且两个向量全部为-128，输出4194304。软件参考已用 MATLAB R2025a 实际运行通过，见 matlab_console.log 与 matlab_results.json。

## 11 本步骤与低资源要求

资源目标仍是一个8乘8乘法器和一个24位累加器。位宽扩大是最大长度完整精度所需，不能为了沿用18位而静默截位。参数配置、计数和比较产生额外少量控制逻辑。

在固定时钟和工具条件下核查综合报告是否推断出预期结构。可综合不等于已经达到最低面积；工具映射可能产生不同实现。没有综合报告时，只能说设计意图是单乘法器复用，不能写成实测硬件资源。
