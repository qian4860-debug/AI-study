# 第007步：共享四路MAC引擎与混合存储

完成日期：2026-10-19。原工程现位于 **D:/学习资料/AI/NYCU-Lab3**；旧目录已移走。本步沿用第006步冻结的模型、数据与数学合同，原223项制品哈希全部通过，未修改任何前序源码或验收记录。

## 本步完成什么

- 两个四路MAC引擎合并为一个；两个三段重定标器合并为一个。
- 两层x/W/bias仍各自保留，使用层号选择地址区域，不在换层时重载权重。
- 实现全BRAM、x分布式/W BRAM、全分布式三种同接口存储配置。
- 原624任务逐层等价、512样本分类结果与每个任务的推理周期均与第006步一致。
- 补充8个满通道边界任务、5个深层复位后不重载RAM重启场景、数据/标签守恒与读写冲突检查。
- 输出逐任务装载/计算/桥接/阻塞计数，同器件综合资源与时序估计，并绑定源码SHA256。

推荐混合版相对双引擎基线：LUT减少42.7%、FF减少39.9%、DSP减少50%、RAMB减少75%。如果更重视LUT而BRAM充足，全BRAM版更适合；全分布式版则以更多LUT换取零RAMB。没有统一的资源最优配置。

器件均为xc7a100tcsg324-1，Vivado2025.1，OOC综合后10ns时钟约束估计；**没有布局布线和板端频率验收**。4路INT8乘法映射到LUT，2个DSP主要用于通用重定标，不能将其描述为4个DSP MAC。

## 为什么省硬件而不增加推理周期

第006步本来就按“第一层全部完成，再启动第二层”调度，两个引擎从不同时计算。合并后复用这段空闲硬件；量化器的tag、层号与存储写保护保证换层不串数据。

无停顿16–8–2，片内转发仍为104拍：层1运行83拍、层2运行19拍、两次启动状态共2拍。主机初始装载170写拍，加外部启动拍后275个占用边沿，与第006步一致。主机回写测试仍为132拍（测试台D=16）。该测试还包含非法地址/过早bridge_done探测，不能将28拍差值全部视为硬件固有桥接开销。

MAC数仍为144；不因节省面积而宣称吞吐翻倍。共享后全推理物理MAC槽利用率为144/(4×104)=34.615%，下一步可研究输出方向复用及逐行控制开销。
