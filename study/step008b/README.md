# 第008B步 两路K乘两路输出的四MAC核心

完成日期2026-10-19。先验收并提交第008A步参数驻留，再实现本步2×2数据流。旧4×1版本完整保留；新版本适合当前16–8–2模型，**并非所有形状都更快**。

## 已测收益与成本

|---|---:|---:|
| 计算至最终握手 | 104拍 | 79拍 |
| 冷加载含170写拍及启动 | 275边沿 | 250边沿 |
| 热推理含16写拍及启动 | 121边沿 | 96边沿 |

| 两层W有效读取 | 144B | 144B |
| 有效MAC数/发数组数 | 144/36 | 144/36 |
| 混合存储LUT / FF | 1263 / 437 | 1395 / 496 |
| DSP / RAMB | 2 / 4 | 2 / 4 |

以增加132 LUT、59 FF换得当前模型计算周期减少25拍（24.0%）；x读取减半，总操作数读取由288B降至216B。参数驻留叠加后热推理96个占用边沿已经实际RTL测得，不是结构推算。边沿口径不包含额外软件/驱动间隙；没有测板端时间、真实DRAM或功耗。

## 如何工作

四个乘法器仍然只有四个，分为两个输出上下文，每个输出有两路K部分和。每拍读两个x，分别广播给两行W；tile结束得到两个dot，依次送bias/ReLU和唯一的三段重定标器。两层继续共享同一FC核心、量化器和完整分区RAM。

W银行变为`{row[0],j[0]}`，银行内地址为`{layer,row[2:1],j[7:1]}`，维持4×1024×8的4096B容量。外部主机地址仍为row*256+j，改变的是内部解码。x仍为4银行、合计512B，只启用本组需要的两个银行。

同步RAM的x银行对选择随读请求寄存，不能用已经自增的实时rd_addr来选择上一拍响应。奇数K和奇数输出数分别mask；无效输出行不能写入量化器或产生last。完整合同见[接口说明](INTERFACES.md)。

## 实际验收

- 三种存储各975个主要任务：原632加343个K/H/O独立形状，每种另完成5次深层复位后重启。
- 每种主回归386933个边沿，9084个输出位置同时核对pre和量化值，512测试样本仍为488/512正确。
- 原4×1 RTL另外实际运行同975案例，确认所有数值/index一致，而不是只用公式模拟对照。
- 2×2另跑519个参数驻留主要任务，含512测试样本、模型切换/上传中断/复位恢复；511次热推理均为96边沿。
- 地址、MAC组/量化在途守恒、写保护、背压、尾mask及输出顺序均检查；三种RAM模式所有事件和周期相同。

## 根据形状选择版本

908个无停顿对照中，2×2快854个、慢53个、相同1个。最差示例K=255/H=1/O=1：原85拍，新149拍，因为单输出无法使用两路输出通道。不能用当前模型的收益替代通用形状结论。

```powershell
$py='C:/Users/11725/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
```
